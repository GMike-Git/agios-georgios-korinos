# Ιερά Μονή Αγίου Γεωργίου Κορινού — Ιστοσελίδα & Σύστημα Διαχείρισης

Στατική ιστοσελίδα (HTML/CSS/JS, χωρίς build step) σε 5 γλώσσες, με ενσωματωμένο σύστημα διαχείρισης περιεχομένου (CMS) που επιτρέπει επεξεργασία κειμένων και φωτογραφιών **χωρίς να αγγίζεις κώδικα**.

**Ζωντανό site:** `https://agios-georgios-korinos.netlify.app`
**Πάνελ διαχείρισης:** `https://agios-georgios-korinos.netlify.app/admin`

---

## 1. Πώς λειτουργεί το σύνολο (η «αλυσίδα»)

```
/admin (Sveltia CMS)  →  GitHub (αποθηκεύει, κρατά ιστορικό)  →  Netlify (ξαναχτίζει αυτόματα)  →  Ζωντανό site
      ↑
   Τοπικό Git (εναλλακτικά, για αλλαγές κώδικα)
```

Κάθε αποθήκευση στο `/admin`, ή κάθε `git push`, ξεκινά αυτόματα νέο deploy στο Netlify — καμία χειροκίνητη ενέργεια δεν χρειάζεται μετά.

**Το CMS που χρησιμοποιούμε είναι το [Sveltia CMS](https://github.com/sveltia/sveltia-cms)** — ενεργά συντηρημένος διάδοχος του παλαιότερου Decap CMS (που δοκιμάσαμε αρχικά, αλλά είχε πραγματικά, τεκμηριωμένα προβλήματα αξιοπιστίας στη διαχείριση εικόνων). Το Sveltia συνδέεται **απευθείας με το GitHub** μέσω ενός προσωπικού token (PAT), όχι μέσω Netlify Identity/Git Gateway (που εγκαταλείψαμε — δες ενότητα 6).

## 2. Δομή αρχείων

```
agios-georgios-korinos/
├── index.html              ← όλος ο κώδικας της σελίδας (HTML+CSS+JS σε ένα αρχείο)
├── content.json              ← ΟΛΑ τα κείμενα, σε 5 γλώσσες — το επεξεργάζεται το CMS
├── images-fixed.json          ← οι 13 σταθερές φωτογραφίες (μία θέση η καθεμία) — το CMS
├── images-gallery.json         ← η λίστα φωτογραφιών του Πολυμέσα — το CMS
├── admin/
│   ├── index.html                ← το ίδιο το CMS (Sveltia)
│   └── config.yml                 ← ορίζει τι πεδία/φόρμες βλέπεις στο /admin
├── images/                          ← οι πραγματικές φωτογραφίες (.jpg/.png)
└── DOCUMENTATION.md                  ← τεχνική τεκμηρίωση της αρχιτεκτονικής
```

**Κανόνας:** το `index.html` δεν περιέχει πια κείμενα/φωτογραφίες «καρφωμένα» — τα διαβάζει δυναμικά από τα παραπάνω `.json` αρχεία κατά τη φόρτωση. Τα ελληνικά κείμενα/η αρχική φωτογραφία παραμένουν ενσωματωμένα ως εφεδρεία, ώστε η σελίδα να μη δείχνει ποτέ κενή ακόμα κι αν κάτι αποτύχει να φορτώσει.

## 3. Πώς συνδέεσαι στο `/admin`

Το Sveltia CMS συνδέεται με ένα **GitHub Personal Access Token (PAT)**, όχι με email/κωδικό:

1. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → **Generate new token**
2. Repository access: **Only select repositories** → `agios-georgios-korinos`
3. Permissions → Repository permissions → **Contents: Read and write**
4. Generate, αντέγραψε το token (ξεκινάει με `github_pat_...`)
5. Στο `/admin`, στην οθόνη σύνδεσης, χρησιμοποίησε την επιλογή **"Sign in with personal access token"** (όχι το κύριο κουμπί GitHub OAuth — αυτό δεν λειτουργεί στο Netlify, δες ενότητα 6) και επικόλλησε το token

> ⚠️ **Το token έχει ημερομηνία λήξης** (όποια όρισες κατά τη δημιουργία, π.χ. 90 μέρες). Όταν λήξει, το `/admin` θα σταματήσει να συνδέεται — απλώς δημιούργησε καινούριο token με τα ίδια βήματα.

## 4. Πώς χρησιμοποιείς το `/admin`

Δύο συλλογές:

### «Περιεχόμενο Ιστοσελίδας»
Όλα τα κείμενα, ομαδοποιημένα ανά ενότητα. Κάθε κείμενο έχει 5 πεδία — ένα ανά γλώσσα.

### «Φωτογραφίες Ιστοσελίδας»
- **«Σταθερές φωτογραφίες»** — 13 συγκεκριμένες θέσεις (π.χ. «Αρχική — Κυρίως φωτογραφία»). Γράφεις τη διαδρομή του αρχείου (π.χ. `images/hero.jpg`) — **πρώτα ανέβασε την ίδια τη φωτογραφία στον φάκελο `images/` μέσω GitHub**, μετά γράψε εδώ τη διαδρομή της.
- **«Πολυμέσα (Γκαλερί)»** — λίστα φωτογραφιών με κουμπί **"+ Add"** για προσθήκη νέας, οποτεδήποτε.

Μετά από κάθε αλλαγή, πάτα **Save/Publish** — το CMS στέλνει αυτόματα commit στο GitHub, το Netlify ξαναχτίζει μόνο του.

## 5. Πώς κάνεις αλλαγές στον ίδιο τον κώδικα (δομή, σχεδίαση, νέες λειτουργίες)

Το CMS καλύπτει μόνο κείμενα/φωτογραφίες. Για οτιδήποτε άλλο χρειάζεται επεξεργασία του `index.html`/`admin/config.yml` απευθείας.

**Τοπικά, με Git** (προτεινόμενο):
```bash
git clone https://github.com/GMike-Git/agios-georgios-korinos.git
cd agios-georgios-korinos
git pull                      # πριν ξεκινήσεις, πάντα — αν έγιναν αλλαγές μέσω CMS
# ... κάνε τις αλλαγές σου ...
git add .
git commit -m "περιγραφή αλλαγής"
git push
```

**Μέσω browser** (εναλλακτικά): GitHub repository → "Add file" → "Upload files". Πρόσεξε: το σύρσιμο μεμονωμένων αρχείων δεν διατηρεί δομή υποφακέλων — αν χρειάζεσαι να ανεβάσεις έναν φάκελο, σύρε τον ίδιο τον φάκελο.

## 6. Netlify — ρυθμίσεις που πρέπει να παραμείνουν σωστές

- **Site configuration → Build & deploy → Continuous deployment**: πρέπει να δείχνει `Current repository: GMike-Git/agios-georgios-korinos` (**όχι** "Not linked").
- **Publish directory**: ρίζα του repository. **Build command**: κενό. **Branch**: `main`.
- Το **Netlify Identity / Git Gateway** (που ρυθμίσαμε αρχικά για το Decap CMS) **δεν χρησιμοποιείται πια** — το Sveltia CMS συνδέεται απευθείας με GitHub μέσω PAT. Μπορείς να τα αφήσεις ανενεργά χωρίς πρόβλημα, ή να τα απενεργοποιήσεις εντελώς από Identity settings αν θες να καθαρίσεις.

## 7. Αντιμετώπιση προβλημάτων (από πραγματικές δυσκολίες που λύσαμε)

| Σύμπτωμα | Αιτία | Λύση |
|---|---|---|
| Αλλαγές στο GitHub δεν εμφανίζονται ποτέ στο ζωντανό site | Το Netlify site δεν ήταν συνδεδεμένο (linked) με το GitHub repo | Site configuration → Build & deploy → Continuous deployment → **Link repository** |
| `/admin` δείχνει "Page not found" | Ο φάκελος `admin/` δεν ανέβηκε σωστά (μόνο τα αρχεία μέσα του, όχι ο ίδιος ο φάκελος) | Ξαναανέβασε σέρνοντας **ολόκληρο** τον φάκελο `admin/` |
| Decap CMS: "Oops, you've missed a required field" σε πεδία εικόνας, ενώ τα δεδομένα ήταν σωστά στο GitHub | Δύο ξεχωριστά προβλήματα: (α) Git Gateway media/blob API ασταθές (`ERR_CONNECTION_RESET`), (β) **ασυμφωνία ένθεσης** ανάμεσα σε `config.yml` και το πραγματικό JSON (το config περίμενε τα πεδία στην κορυφή του αρχείου, ενώ το JSON τα είχε τυλιγμένα μέσα σε ένα επιπλέον `"fixed": {...}` επίπεδο) | Εγκατάλειψη Decap για Sveltia CMS (github backend + PAT) **και** διόρθωση του `config.yml` ώστε η ένθεση των πεδίων να ταιριάζει ακριβώς με τη δομή του πραγματικού JSON αρχείου |
| Sveltia CMS: "Sign in with GitHub" δίνει `Not Found` στο `api.netlify.com/auth` | Το Sveltia δεν υποστηρίζει το backend `git-gateway`· το Netlify OAuth proxy δεν καλύπτει σωστά το backend `github` για CMS τρίτων | Σύνδεση με **Personal Access Token** αντί για OAuth (δες ενότητα 3) |
| Δεν βρίσκεις «Git Gateway» στο μενού Identity | Το Netlify το έχει κάνει λιγότερο εμφανές στα νεότερα sites (πλέον άσχετο για εμάς) | Δεν χρειάζεται πια — δες ενότητα 6 |
| Νέο deploy δεν ξεκινά ποτέ μόνο του | Το site δεν ήταν συνδεδεμένο με Git | Deploys → **Trigger deploy** → **Deploy site** |

**Γενικό μάθημα από όλη τη διαδικασία:** όταν ένα σφάλμα επιμένει ίδιο σε δύο εντελώς διαφορετικά προγράμματα (Decap **και** Sveltia απέτυχαν με τον ίδιο τρόπο στο ίδιο σημείο), το πρόβλημα είναι σχεδόν σίγουρα στα δικά μας δεδομένα/ρυθμίσεις, όχι στο λογισμικό — αυτό μας οδήγησε τελικά στη σωστή διάγνωση.
