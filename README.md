# Ιερά Μονή Αγίου Γεωργίου Κορινού — Ιστοσελίδα & Σύστημα Διαχείρισης

Στατική ιστοσελίδα (HTML/CSS/JS, χωρίς build step) σε 5 γλώσσες, με ενσωματωμένο σύστημα διαχείρισης περιεχομένου (CMS) που επιτρέπει επεξεργασία κειμένων και φωτογραφιών **χωρίς να αγγίζεις κώδικα**.

**Ζωντανό site:** `https://agios-georgios-korinos.netlify.app`
**Πάνελ διαχείρισης:** `https://agios-georgios-korinos.netlify.app/admin`

---

## 1. Πώς λειτουργεί το σύνολο (η «αλυσίδα»)

```
/admin (CMS)  →  GitHub (αποθηκεύει, κρατά ιστορικό)  →  Netlify (ξαναχτίζει αυτόματα)  →  Ζωντανό site
      ↑
   Τοπικό Git (εναλλακτικά, για αλλαγές κώδικα)
```

Κάθε αποθήκευση στο `/admin`, ή κάθε `git push`, ξεκινά αυτόματα νέο deploy στο Netlify — καμία χειροκίνητη ενέργεια δεν χρειάζεται μετά.

## 2. Δομή αρχείων

```
agios-georgios-korinos/
├── index.html          ← όλος ο κώδικας της σελίδας (HTML+CSS+JS σε ένα αρχείο)
├── content.json         ← ΟΛΑ τα κείμενα, σε 5 γλώσσες — το επεξεργάζεται το CMS
├── images.json           ← όλες οι φωτογραφίες (σταθερές θέσεις + λίστα Πολυμέσων) — το επεξεργάζεται το CMS
├── admin/
│   ├── index.html        ← το ίδιο το CMS (Decap CMS)
│   └── config.yml         ← ορίζει τι πεδία/φόρμες βλέπεις στο /admin
├── images/                ← οι πραγματικές φωτογραφίες (.jpg/.png)
└── DOCUMENTATION.md        ← τεχνική τεκμηρίωση της αρχιτεκτονικής
```

**Κανόνας:** το `index.html` δεν περιέχει πια κείμενα/φωτογραφίες «καρφωμένα» — τα διαβάζει δυναμικά από τα `content.json` και `images.json` κατά τη φόρτωση. Τα ελληνικά κείμενα παραμένουν ενσωματωμένα ως εφεδρεία, ώστε η σελίδα να μη δείχνει ποτέ κενή ακόμα κι αν κάτι αποτύχει να φορτώσει.

## 3. Πώς χρησιμοποιείς το `/admin`

Μπες στο `/admin`, συνδέσου με email + κωδικό. Θα δεις δύο συλλογές:

### «Περιεχόμενο Ιστοσελίδας»
Όλα τα κείμενα, ομαδοποιημένα ανά ενότητα (π.χ. «Ιστορικό — «Η Μονή του Αγίου Γεωργίου...»»). Κάθε κείμενο έχει 5 πεδία — ένα ανά γλώσσα (Ελληνικά, English, Srpski, Български, Română). Αλλάζεις το κείμενο, πατάς **Save** πάνω δεξιά.

### «Φωτογραφίες Ιστοσελίδας»
- **13 σταθερές φωτογραφίες** (π.χ. «Αρχική — Κυρίως φωτογραφία», «Η Αδελφότητα — Καθηγουμένη») — ανοίγεις το πεδίο, πατάς πάνω στην εικόνα, επιλέγεις/ανεβάζεις νέα.
- **Λίστα «Πολυμέσα»** — οι φωτογραφίες της γκαλερί. Κουμπί **"+ Add"** για προσθήκη νέας, οπουδήποτε, οποτεδήποτε. Κάθε φωτογραφία έχει προαιρετικό μέγεθος (Κανονικό/Ψηλό/Πλατύ) που καθορίζει πώς εμφανίζεται στο πλέγμα.

> ⚠️ Μετά από κάθε αλλαγή, πάτα **Save** και μετά **Publish** (αν υπάρχει ξεχωριστό κουμπί) — το CMS στέλνει αυτόματα commit στο GitHub, το Netlify ξαναχτίζει μόνο του.

## 4. Πώς κάνεις αλλαγές στον ίδιο τον κώδικα (δομή, σχεδίαση, νέες λειτουργίες)

Το CMS καλύπτει μόνο κείμενα/φωτογραφίες. Για οτιδήποτε άλλο (νέα ενότητα, αλλαγή σχεδίασης, νέο εφέ) χρειάζεται επεξεργασία του `index.html`/`admin/config.yml` απευθείας.

**Τοπικά, με Git** (προτεινόμενο, γρηγορότερο):
```bash
git clone https://github.com/GMike-Git/agios-georgios-korinos.git
cd agios-georgios-korinos
git pull                      # πριν ξεκινήσεις, πάντα — αν έγιναν αλλαγές μέσω CMS
# ... κάνε τις αλλαγές σου ...
git add .
git commit -m "περιγραφή αλλαγής"
git push
```

**Μέσω browser** (εναλλακτικά): GitHub repository → "Add file" → "Upload files", σέρνοντας τα αρχεία/φακέλους. Πρόσεξε: το σύρσιμο μεμονωμένων αρχείων (όχι ολόκληρου φακέλου) **δεν** διατηρεί τη δομή υποφακέλων — αν χρειάζεσαι να ανεβάσεις έναν φάκελο (π.χ. `admin/`), σύρε τον ίδιο τον φάκελο, όχι τα αρχεία μέσα του μεμονωμένα.

## 5. Netlify — ρυθμίσεις που πρέπει να παραμείνουν σωστές

- **Site configuration → Build & deploy → Continuous deployment**: πρέπει να δείχνει `Current repository: GMike-Git/agios-georgios-korinos` (**όχι** "Not linked" — αν ποτέ δείξει "Not linked", καμία αλλαγή στο GitHub δεν θα φτάνει ποτέ στο ζωντανό site).
- **Publish directory**: ρίζα του repository (κενό ή `/`).
- **Build command**: κενό — δεν χρειάζεται build step.
- **Branch**: `main`.

## 6. Αντιμετώπιση προβλημάτων (από πραγματικές δυσκολίες που λύσαμε)

| Σύμπτωμα | Αιτία | Λύση |
|---|---|---|
| Αλλαγές στο GitHub δεν εμφανίζονται ποτέ στο ζωντανό site | Το Netlify site δεν ήταν συνδεδεμένο (linked) με το GitHub repo | Site configuration → Build & deploy → Continuous deployment → **Link repository** |
| `/admin` δείχνει "Page not found" | Ο φάκελος `admin/` δεν ανέβηκε σωστά (π.χ. ανέβηκαν μόνο τα αρχεία μέσα του, όχι ο ίδιος ο φάκελος) | Ξαναανέβασε σέρνοντας **ολόκληρο** τον φάκελο `admin/`, όχι τα αρχεία μεμονωμένα |
| "Δεν βρέθηκαν χρήστες" στο Identity | Φυσιολογικό μήνυμα πρώτης χρήσης | Identity → **Invite users** |
| "Email already registered" | Ο λογαριασμός υπάρχει ήδη | Identity → Users → βρες τον χρήστη → **Send reset password email** |
| "Email not confirmed" στο login | Ο λογαριασμός έμεινε σε ημιτελή κατάσταση από διακοπτόμενη ροή επιβεβαίωσης | Identity → Users → **διάγραψε** τον χρήστη → ξαναπροσκάλεσε από την αρχή |
| Δεν βρίσκεις «Git Gateway» στο μενού Identity | Το Netlify το έχει κάνει λιγότερο εμφανές στα νεότερα sites | Πήγαινε απευθείας: `https://app.netlify.com/sites/ΟΝΟΜΑ-SITE/settings/identity#services` |
| «Το backend της πύλης git δεν επιστρέφει έγκυρες ρυθμίσεις» στο CMS | Γνωστό, ενίοτε ασταθές ζήτημα υπηρεσίας Git Gateway | Απενεργοποίησε και ξανα-ενεργοποίησε το Git Gateway (Identity → Services) |
| "Authentication Error: Invalid state key" κατά το authorize | Το incognito/ιδιωτική περιήγηση μπλοκάρει τον μηχανισμό σύνδεσης | Ξαναδοκίμασε σε **κανονικό** παράθυρο browser, όχι incognito |
| Νέο deploy δεν ξεκινά ποτέ μόνο του | Το site δεν ήταν συνδεδεμένο με Git (δες πρώτη γραμμή του πίνακα) — ή δοκίμασε **Trigger deploy** χειροκίνητα | Deploys → **Trigger deploy** → **Deploy site** |
